# SAIZERIYA ORDER

サイゼリヤの商品名（写真がある場合は写真も）から4桁の注文番号を覚える、非公式の個人制作Webアプリです。**5問クイズ／5品ガチャ／メニューギャラリー**をブラウザで利用できます。

## 公開先

| 環境 | ブランチ | URL |
| --- | --- | --- |
| 本番 | `main` | https://naoiw.github.io/saizeriya-order/ |
| 開発プレビュー | `develop` | https://naoiw.github.io/saizeriya-order/develop/ |

## 主な機能

- **クイズ** — 登録済み114番号から重複なしでランダムに5問。画像のない商品は「画像なし」と表示し、商品名・必要に応じて「すぐに／あとで」「赤／白」を表示し、数字キーや画面キーパッドで4桁を回答。各問の正誤と最後の集計を確認できます。
- **ガチャ** — ボタンを押して初めて、確認済みの通常メニュー35番号から5件の注文番号を**重複あり**で抽選します（過去資料・朝・季節限定は対象外）。再抽選可能で、料理写真と番号も表示。同じ商品が複数回選ばれることがあります。
- **ギャラリー** — メニューをカード／リスト表示し、商品名・注文番号・ラベルで検索、並び替え。提供タイミング違いのデザートや赤白のグラスワインは、1カードに2番号を掲載します。
- **レスポンシブUI** — PC・スマートフォンに対応。クイズ中のスマホ画面は余白やキーパッドを縮小していますが、短い画面ではスクロールを許容します。

現在は**114注文番号（すべてクイズ対象・ギャラリー93カード）**です。既存35件、2026年2月資料からの追加70件、朝サイゼ8件、季節商品1302の1件を収録。**80件は画像URL未設定で「画像なし」と表示**し、5101（セットドリンクバー）も画像なしで有効化しました。参考資料の70番号は2026年11月時点の販売を全件確認したものではありません。

## 使い方

1. 公開URLを開き、上部から「クイズ」「ガチャ」「ギャラリー」を選びます。
2. クイズは「クイズをはじめる」を押し、5問に回答します。画像がない場合は商品名からそのまま回答でき、設定済みの画像が読み込めない場合はスキップできます。
3. ガチャは**「ガチャを回す」**を押すまで結果が出ません。結果表示後は「もう一度ガチャを回す」で再抽選できます。
4. ギャラリーでは番号・名前を検索し、カードとリストを切り替えられます。

選択中のモードはURLハッシュ（`#quiz` / `#gacha` / `#gallery`）に反映されます。F5で同じモードを開きますが、**ガチャ結果はリセットされ、ボタンを押すまで再抽選しません**。

## 技術スタック

- React 19 / TypeScript 5 / Vite 7 / CSS
- Node.js 22 / pnpm 9（GitHub Pagesのビルドでは9.14.2）
- Node.js組み込みテスト（`node --test`）
- GitHub Actions（CI）/ GitHub Pages（本番・開発プレビュー）

## ローカル開発

Node.js 20.19以降または22.12以降（Vite 7の要件）とpnpmを準備してください。

```bash
git clone https://github.com/naoiw/saizeriya-order.git
cd saizeriya-order
git switch develop
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

表示される開発サーバーのURL（通常 `http://localhost:5173`）をブラウザで開きます。

```bash
pnpm test:collector
pnpm test:quiz
pnpm test:gacha
pnpm test:gallery
pnpm test:dataset
pnpm check:dataset
pnpm build
```

`pnpm build` は型チェックとViteの本番ビルドを行い、生成物を `dist/` に出力します。

## ブランチ・デプロイ運用

1. 通常の作業は `develop` 向けのPRで行い、CI成功後にマージします。
2. `develop` のpushによるCIが成功すると、GitHub Pagesの `/develop/` を更新します。
3. 本番公開は **`develop` → `main` のPR** をマージします。`main` のpushで本番を更新します。
4. `main` と `develop` は維持し、マージ済みの一時作業ブランチは整理します。

本番とプレビューは**1つのGitHub Pagesサイト**内で公開しています。詳細は[デプロイ構成](docs/DEPLOYMENT.md)を参照してください。
