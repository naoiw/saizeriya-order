# データセットと画像管理

## 保存形式

唯一のメタデータソースは `src/data/menu.json`（配列）です。

```json
[
  {
    "code": "2101",
    "name": "ミラノ風ドリア",
    "image": "/images/2101.webp",
    "imageSource": "https://www.saizeriya.co.jp/files/...",
    "pageUrl": "https://www.saizeriya.co.jp/menu-popular/2101/"
  }
]
```

- `code`: **文字列**の4桁番号。先頭ゼロに対応でき、数値として扱わない。
- `name`: 出題・一覧表示に使う商品名。
- `image`: ローカルの `public/images/` にある相対パス（ブラウザからは `/images/...`）。
- `imageSource`: 画像が掲載されていた公式URL（出典・更新確認用）。
- `pageUrl`: 該当商品詳細ページ（出典）。

`code` は一意とし、画像や商品名の変更時に追跡できるよう出典URLを残します。現在のバリデーションは `src/lib/menu.ts` です。

## 画像収集

```bash
npm run collect:menu -- --dry-run
npm run collect:menu -- --limit 5
npm run collect:menu
npm run collect:menu -- --force
```

収集スクリプトは標準Node.js APIのみで動作します。人気メニュー一覧から `/menu-popular/NNNN/` 形式のリンクを探し、詳細ページの `<title>` から商品名、`/files/NNNN_...` 形式の画像から写真を特定します。取得後、WebP/JPEG/PNGの画像マジックバイトを検証して保存します。画像は最大5MB、逐次アクセスと待機時間を設けています。

`src/data/menu.json` は既存データを残しながら、取得成功レコードのみ更新する方式です。**販売終了・サイト更新により消えた商品は自動削除しません。** 更新時は登録済み商品との突き合わせをしてください。スキップされた項目のログを確認し、不足分は手動検証・補完が必要です。

`public/images/` はGit管理対象外。公開デプロイで収集済み画像を同梱しない設計のため、ローカル動作を前提とします。直接公式サイト画像をホットリンクする設計ではありません。

## 運用上の注意

- 4桁注文番号と商品名は変更の可能性があります。取得時点のメニューとの差分を確認してください。
- 一品に複数の注文番号が存在するケース（例: 提供タイミング別）は、現行スキーマでは1件1コードに固定されます。クイズ実装までに設問条件か許容解答を設計する必要があります。
- 商品ごとの対応ミスを防ぐため、画像ファイル名が該当コードで始まらない場合は採用しません。
- 自動収集はアクセス制限回避や大量並列アクセスを意図していません。サイト側が変更・拒否した場合は停止して確認してください。
- 将来、完全なグランドメニュー対応が必要なら電子ブックから画像切り出しを行う別インポーターを追加する方針です。
